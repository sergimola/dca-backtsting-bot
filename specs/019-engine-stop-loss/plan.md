# Implementation Plan: Engine Stop-Loss Mechanism

**Branch**: `019-engine-stop-loss` | **Date**: April 3, 2026 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `/specs/019-engine-stop-loss/spec.md`

---

## Summary

Add a configurable stop-loss mechanism to the DCA backtesting engine. When enabled, the engine evaluates a percentage-based trigger price on each candle's Low. If the price breaches the trigger — and stays below for a configurable timeout — the position closes at the breaching candle's Close price as a taker order. Two baseline modes are supported: `first_entry` (fixed trigger from the base order) and `average_entries` (trigger updates after each safety order fill). The feature adds 4 config fields, 6 position runtime state fields, 1 new domain event, 2 new engine result fields, 1 Postgres migration, and UI changes to the Optimizer Configurator and Leaderboard.

**Key design decision**: Stop-loss overrides `exitOnLastOrder` when both are enabled, ensuring the SL mechanism always governs position exit regardless of order fill completion.

## Implementation Phases

### Phase A: Go Engine — Config & Domain (core-engine)

**Scope**: Pure domain changes. No I/O, no HTTP.

1. **`domain/config/config.go`** — Add 4 new fields to `Config` struct:
   - `stopLossEnabled bool`
   - `stopLossPercent decimal.Decimal`
   - `stopLossBaseline string` (enum: `"first_entry"` | `"average_entries"`)
   - `stopLossTimeoutMinutes int`
   - Add `With*` functional options for each
   - Add validation in `Validate()`: when enabled, percent > 0 and ≤ 100; baseline valid; timeout ≥ 0
   - Add fields to `configJSON` struct + `ToJSON()` / `FromJSON()`
   - Default: `stopLossEnabled = false`, `stopLossBaseline = "average_entries"`, `stopLossTimeoutMinutes = 0`

2. **`domain/position/events.go`** — Add `StopLossExecutedEvent` struct (fields: run_id, trade_id, timestamp, trading_pair, execution_price, size, realized_loss, fee). `EventType()` returns `"stop_loss.executed"`. Add `"stop_loss"` as a documented reason value in `TradeClosedEvent` code comments.

3. **`domain/position/position.go`** — Add 6 SL runtime fields to `Position` struct:
   - `StopLossEnabled bool`
   - `StopLossPercent decimal.Decimal`
   - `StopLossBaseline string`
   - `StopLossTimeoutMinutes int`
   - `SlTriggerPrice decimal.Decimal`
   - `SlBreachTimestamp time.Time` (value, not pointer — avoids heap escape in hot loop; check with `.IsZero()`, clear with `time.Time{}`)

4. **`domain/position/minute_loop.go`** — Three changes:
   - a. **exitOnLastOrder guard**: wrap the early-exit block with `if pos.ExitOnLastOrder && !pos.StopLossEnabled`
   - b. **SL trigger update in Step 3b**: after SO fills, if `stopLossBaseline == "average_entries"`, recompute `pos.SlTriggerPrice = pos.AverageEntryPrice.Mul(one.Sub(pct.Div(hundred)))`. If breachTimestamp was active and new trigger > candle.Low, reset breach.
   - c. **Step 3c.5**: after liquidation check, before TP check — if `pos.StopLossEnabled && !pos.SlTriggerPrice.IsZero()`: check `candle.Low ≤ SlTriggerPrice`; handle immediate (timeout=0) or timeout-based execution; emit `StopLossExecutedEvent` + `TradeClosedEvent(reason="stop_loss")`.
   - d. **TP clears breach**: at top of Step 3d, clear `pos.SlBreachTimestamp = time.Time{}`.

5. **`domain/position/stop_loss_test.go`** — New test file with BDD test functions:
   - `TestSL_ImmediateExecution_T001`: immediate breach, timeout=0
   - `TestSL_TimeoutExecution_T002`: timeout=60, breach holds ≥ 60 min
   - `TestSL_TimeoutReset_T003`: breach, recovery, no stop
   - `TestSL_FirstEntryBaseline_T004`: trigger fixed from base order
   - `TestSL_AverageEntriesBaseline_T005`: trigger updates on SO fill
   - `TestSL_TPWinsDuringSLTimeout_T006`: TP fires during active SL timeout
   - `TestSL_ExitOnLastOrderOverride_T007`: SL enabled overrides exitOnLastOrder
   - `TestSL_OpeningCandle_T008`: SL evaluates on position-opening candle
   - `TestSL_Disabled_Regression_T009`: SL disabled → same result as pre-feature
   - `TestSL_CanonicalTrigger_T010`: exact decimal test vectors from spec

### Phase B: Go Engine — CMD Layer (core-engine/cmd/engine)

**Scope**: Engine I/O contract and aggregation.

6. **`cmd/engine/main.go`**:
   - Add 4 fields to `EngineRequest` struct
   - Map them to config `With*` options when building `domainconfig.Config`
   - Add `TotalStopsTriggered int` and `TotalTakeProfits int` to `EngineResultPayload` (`total_take_profits` is ephemeral — not persisted to Postgres; only `total_stops_triggered` is written to the DB)
   - Add `WinRate float64 \`json:"winRate"\`` to `PnlSummaryOutput` — populated via `aggregationResult.winRate.InexactFloat64()` (decimal-computed in aggregator, float64 conversion at JSON boundary only)

7. **`cmd/engine/aggregator.go`**:
   - Track `stopLossCount int` and `takeProfitCount int` by inspecting `TradeClosedEvent.Reason`
   - Compute `winRate decimal.Decimal` using `decimal.NewFromInt(int64(tp)).Div(decimal.NewFromInt(int64(tp+sl))).Round(8)`; return `decimal.Zero` when both zero (constitution MUST: quantitative calculations use fixed-point)
   - Convert to `float64` via `winRate.InexactFloat64()` **only** at the JSON serialization boundary in `main.go`
   - Expose counts and `winRate decimal.Decimal` in `aggregationResult`; main.go writes them to `EngineResultPayload`

### Phase C: Application Orchestrator — Config Wiring (core-engine/application)

**Scope**: Pass SL fields from `domainconfig.Config` to `Position` at open.

8. **`application/orchestrator/orchestrator.go`**:
   - After `position.NewPosition(...)`, copy SL fields from `oc.DomainConfig` to `pos`:
     ```go
     pos.StopLossEnabled        = oc.DomainConfig.StopLossEnabled()
     pos.StopLossPercent        = oc.DomainConfig.StopLossPercent()
     pos.StopLossBaseline       = oc.DomainConfig.StopLossBaseline()
     pos.StopLossTimeoutMinutes = oc.DomainConfig.StopLossTimeoutMinutes()
     ```
   - Compute initial `SlTriggerPrice` from base order entry price at position open (for `first_entry` mode), or leave zero (for `average_entries`, it's set after first fill in minute_loop).
   - This follows the exact same pattern as `pos.ExitOnLastOrder = oc.DomainConfig.ExitOnLastOrder()`.

### Phase D: API & Database (orchestrator/api)

**Scope**: Postgres schema, migration, type wiring.

9. **`drizzle/0005_019_stop_loss_kpis.sql`** (NEW):
   ```sql
   ALTER TABLE "sweep_run_summaries"
     ADD COLUMN "total_stops_triggered" integer DEFAULT 0 NOT NULL;
   ```

10. **`src/db/schema.ts`**: Add `totalStopsTriggered: integer('total_stops_triggered').notNull().default(0)` to `sweepRunSummaries`.

11. **`src/types/index.ts`**: Add 4 SL fields to `ApiSweepRunConfig` (all optional). Add `total_stops_triggered: number` and `total_take_profits: number` to `EngineResultLine`. Add `winRate: number` to `StoredPnlSummary` (if not already present).

12. **`src/services/SweepPersistenceService.ts`**: Map `engineResult.total_stops_triggered` to `totalStopsTriggered` when inserting/updating `sweepRunSummaries`.

### Phase E: Frontend UI (frontend/src)

**Scope**: Optimizer Configurator and Leaderboard.

13. **`components/OptimizerConfigurator.tsx`** (or equivalent):
    - Add `stop_loss_enabled` toggle switch
    - Conditionally show (when SL enabled):
      - `stop_loss_percent`: numeric input, sweepable (fixed/range/array)
      - `stop_loss_baseline`: dropdown, NOT sweepable (`"first_entry"` | `"average_entries"`)
      - `stop_loss_timeout_minutes`: numeric input, sweepable (fixed/range/array)

14. **`components/LeaderboardGrid.tsx`** (or equivalent):
    - Add `total_stops_triggered` column: integer display, sortable, filterable
