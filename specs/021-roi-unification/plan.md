# Implementation Plan: Unified ROI Calculation

**Branch**: `021-roi-unification` | **Date**: 2026-04-07 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/021-roi-unification/spec.md`

## Summary

The Go engine computes ROI as `netProfit / (initialBalance + totalAdditions) × 100` and returns it
in `pnlSummary.roi`. Three frontend sites currently re-derive ROI locally using only
`accountBalance` as the denominator, overstating returns whenever `monthlyAddition > 0`. This
feature introduces a single shared `calculateRoi` utility in the frontend, makes all rendering
paths consume `pnlSummary.roi` directly (or the utility as a fallback), and deletes the duplicate
derivation code in `useResultsMetrics`, `metricsCalculator`, and `RunCard`.

## Implementation Phases

### Phase A — New shared utility

Create `frontend/src/services/roiCalculator.ts`:
- Export `calculateRoi(netProfit, initialBalance, totalAdditions): number`
- Uses `Decimal.js` for the division
- Returns 0 when denominator is ≤ 0

Write `frontend/src/__tests__/services/roiCalculator.test.ts`:
- All 5 canonical test cases from spec
- Zero-denominator guard

### Phase B — Fix useResultsMetrics (full dashboard)

In `useResultsMetrics.ts`:
- Remove `const roi = accountBalance > 0 ? (netProfit / accountBalance) * 100 : 0`
- Replace with `const roi = pnlSummary.roi` (consume engine value directly)
- Keep `totalAdditions` extraction (used for `accountEquity = trueCapitalAvailable + netProfit`)

Update `useResultsMetrics.test.ts`:
- Change the roi test to expect `5.0` (the pnlSummary.roi from the mock), not the re-derived `1.3`

### Phase C — Fix metricsCalculator + RunCard (run list)

In `metricsCalculator.ts`:
- Remove `roi` from the `NetMetrics` return type and computation

In `RunCard.tsx`:
- Remove the inline `(np / balance) * 100` re-derivation
- Always use `completedResults.pnlSummary.roi` as `displayNetRoi`
- Derive `displayNetProfit` from `pnlSummary.roi` and `accountBalance` for display only
  (`displayNetProfit = (pnlSummary.roi / 100) * (initialBalance + totalAdditions)`)

### Phase D — Validation

Run the full frontend test suite:
```bash
cd frontend && npm test
```
All tests must pass (Green Light Protocol).
